# cod-agent — «Оля», AI-продавець у Telegram для COD

Замінює колл-центр на товарних лендингах з оплатою при отриманні (Нова пошта, Україна).
Людина з лендингу потрапляє в Telegram — бот сам збирає замовлення, кладе його в CRM
підтвердженим, веде клієнта до викупу і продає бандл. Дзвінків немає, все листуванням.

**Що вміє:**

- збирає замовлення за 4 тапи: номер кнопкою → ім'я з профілю → геолокація → найближче відділення НП;
- створює замовлення в LP-CRM одразу підтвердженим (не потрібен прозвон);
- сам стежить за ТТН і статусом посилки: «поїхала» → «у відділенні» → нагадування на 3-й і 5-й день;
- допродає курс 60 днів **після** підтвердження (персональний банер з іменем);
- відповідає на 13 типових заперечень миттєво, без ШІ; складне — передає людині;
- після викупу веде далі: догляд день 1, відгук через тиждень, новий флакон на 25-й день;
- A/B-тест трьох «шкіл продажу» одночасно (Подруга / Продавець / Експертка).

## Керування: пульт

Усе керування — у веб-пульті, встановлювати нічого не треба. Посилання і код доступу
дає власник.

| Вкладка | Що там |
|---|---|
| **Пульт** | скільки заробили, approve, апсейл, середній чек, маржа, викуп; воронка; грошова воронка «скільки дійшло до каси»; A/B шкіл; пульс 14 днів; останні замовлення |
| **Діалоги** | усі переписки як у месенджері + **відповідь клієнту від себе** (бот у цьому чаті стає на паузу, кнопка «↩ боту» повертає) |
| **Сценарій** | увесь шлях клієнта покроково з реальними текстами + **редагування** будь-якої фрази: зберігається одразу, без перезапуску |
| **Розсилка** | сегменти бази (викупили / без курсу / час нового флакона / загублені), прев'ю і відправка |

**Встановити пульт як застосунок на телефон:** відкрити посилання → «Поділитись» →
«На екран Домів». Відкривається без адресного рядка, як звичайний застосунок.

Пуш про кожне нове замовлення приходить у Telegram власнику; вимикається тумблером
унизу пульта.

## Своя копія (деплой)

Потрібні: VPS з Ubuntu, Python 3.12+, домен або nip.io, Caddy (HTTPS автоматом).

```bash
git clone <цей-репозиторій> cod_agent && cd cod_agent
cp config.env.example config.env      # заповнити токени, chmod 600
python3 -m venv venv && venv/bin/pip install -r requirements.txt
venv/bin/python -m pytest -q          # 20 тестів мають бути зелені
```

Що вписати в `config.env`:

| Змінна | Де взяти |
|---|---|
| `BOT_TOKEN` | @BotFather у Telegram |
| `ADMIN_IDS` | ваш Telegram user id (кому пуші й `/stats`) |
| `LPCRM_SUBDOMAIN`, `LPCRM_API_KEY`, `LPCRM_API_KEY_IN` | кабінет LP-CRM: «вихідний» ключ для читання, «вхідний» — для створення замовлень |
| `LPCRM_SITE`, `LPCRM_OFFICE`, `LPCRM_STATUS_CONFIRMED` | налаштування вашого кабінету |
| `CLAUDE_CODE_OAUTH_TOKEN` | `claude setup-token` (підписка) — для вільного тексту; без нього працюють кнопки і банк заперечень |
| `ADMIN_API_KEY` | вигадати довгий рядок — це код доступу до дій у пульті |
| `API_PORT` | 7810 (пульт), Caddy проксіює `/api/*` сюди |

Продукт, ціни, набори, тексти трьох шкіл і банк заперечень — у `offer.yaml`.
Це єдине джерело правди про ціни: бот ніколи не називає суму, якої там немає.

Запуск на сервері:

```bash
bash deploy/deploy.sh        # rsync → venv → systemd → рестарт
```

Caddy (роздає пульт і проксіює API):

```
ваш-домен {
    encode gzip
    reverse_proxy /api/* 127.0.0.1:7810
    root * /srv/cod_agent/var
    file_server
    rewrite / /dashboard.html
}
```

## Структура

```
bot.py            запуск: polling + фонові джоби + веб-API в одному процесі
offer.yaml        товар, ціни, набори, тексти трьох шкіл, банк заперечень
core/             стани замовлення, інструменти ШІ, гейти, черга в CRM, планувальник
clients/          LP-CRM, Нова пошта, Claude
tg/               хендлери Telegram, клавіатури, тексти
web/              веб-API пульта і сторінки (пульт, діалоги, сценарій, розсилка)
obs/              метрики воронки і грошей
db/migrations/    схема SQLite
deploy/           systemd-юніт і скрипт деплою
tests/            20 тестів наскрізного сценарію
```

## Безпека

- `config.env` ніколи не потрапляє в git (у `.gitignore`), на сервері `chmod 600`;
- дії в пульті (відповідь клієнту, розсилка, правка сценарію) — тільки з `ADMIN_API_KEY`;
- бот не просить передоплат і не збирає дані карток;
- ціни беруться лише з `offer.yaml`, вигадані суми і дати блокуються перевіркою перед відправкою.
