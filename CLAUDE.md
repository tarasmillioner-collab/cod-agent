# cod-agent — «Оля», Telegram-продавець для COD (Olavita)

Це БОЙОВИЙ сервер. Бот прямо зараз спілкується з живими клієнтами і створює замовлення в CRM.

## Головне правило

Будь-яка правка застосовується ТІЛЬКИ так:

    bash deploy/apply.sh "Ім'я" "що змінили"

Скрипт сам: тести → перевірка offer.yaml → рестарт → перевірка, що бот піднявся → коміт у GitHub.
Якщо тести червоні або бот не встав — нічого не застосується. Це і є захист.

НЕ робити руками: `systemctl restart`, редагування `var/cod.db`, `git push` в обхід apply.sh.

## Де що лежить

| Що | Файл |
|---|---|
| Товар, ціни, набори, тексти трьох шкіл, банк заперечень | `offer.yaml` — єдине джерело цін |
| Ключі Telegram, CRM, коди доступу до пульта | `config.env` (не в git, chmod 600) |
| Кроки замовлення, гейти, черга в CRM, планувальник | `core/` |
| Тексти повідомлень і клавіатури | `tg/` |
| Пульт: сторінки і веб-API | `web/` |
| Метрики воронки і грошей | `obs/` |
| База клієнтів і замовлень | `var/cod.db` (бекап щодня 04:40 у `/srv/backups/cod_agent`) |

## Закони проєкту

1. **Ціни лише з offer.yaml.** Жодних сум у коді — гейт `core/guards.py` ріже відповіді з чужими цифрами.
2. **Мова — українська**, звертання лише на ім'я в кличному відмінку, ніколи на прізвище.
3. **Ніяких вигаданих дедлайнів і знижок.** Єдиний дедлайн — термін зберігання на Новій пошті.
4. **Апсейл — тільки після підтвердження замовлення**, ніколи на вході.
5. **Тексти краще правити з пульта** (вкладка «Сценарій») — вони перекривають offer.yaml і діють одразу, без деплою.
6. Перед правками — `git log --oneline -10`: можливо, колега вже щось змінив.

## Корисні команди

    systemctl status cod-agent          # чи живий бот
    journalctl -u cod-agent -n 50       # останні логи
    venv/bin/python -m pytest -q tests  # тести (20 шт)
    git log --oneline -10               # історія правок
